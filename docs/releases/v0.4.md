# StickLab v0.4 — Living Stick Figures

StickLab v0.4 adds small autonomous agents to the same physical world used by Free Sandbox, v0.3 machines, destruction, and three physics challenges. It retains a single-file offline build.

## New systems

- **Resident tool:** spawn named living figures. **Ragdoll** remains a separate passive physics tool. Existing figures from v0.1–v0.3 imports default to passive rather than unexpectedly coming alive.
- **Independent inhabitants:** curious, cautious, and helpful personalities choose between exploring, investigating nearby loose balls, reacting to falling hazards, and resting. Decisions are deterministic and throttled. Names and a small bounded memory of hazards and motor interactions are stored in scene files.
- **Physics-based locomotion:** agent brains return steering/jump intentions. The controller converts them to the same momentum/joint nudges used by player controls; actors cannot teleport, float past obstacles, or bypass goal conditions.
- **Obstacle and hazard awareness:** agents detect nearby fixed boxes and attempt a jump if grounded, move away from falling objects, and retain a hazard count and last known hazard position. This is local reactive navigation, not global pathfinding.
- **Assistance:** put a resident in Help mode to make it approach a nearby ball (or the active physics challenge's target ball) and physically push through collision. A helpful agent may activate a nearby unpowered wheel when pursuing an objective. It does **not** guarantee solving all puzzles.
- **Player takeover:** use Grab to select an inhabitant and steer directly; its AI stops applying impulses while selected. Release Control returns it to autonomous behavior. AI can be disabled globally without pausing physics or manual figure controls.
- **Behavior UI:** select Explore, Help or Rest; inspect the selected resident's name, personality and current intent; in-world name labels show up to the active profile's AI budget.
- **Offline and performance:** no network AI, generated animation files or external libraries. Eco performs a maximum of two active resident decisions every 30 physics ticks per resident; Standard supports five at 18-tick intervals; High supports eight at 12-tick intervals. Excess characters remain physical ragdolls without AI updates. Decision scans are capped.

## Scene format and compatibility

v4 worlds contain `aiEnabled` and resident group fields `ai`, `name`, `personality`, `mode`, and bounded `memory` values. The import validator rejects malformed memories, unsupported modes, invalid names and broken body/group references *before* replacing the active scene. v1–v3 scenes still import, and legacy local save slots fall back to the previous versions when no v4 save exists.

## Verification and limits

GitHub Actions checks syntax, scene migrations, decision logic, manual takeover, AI toggle, character movement, three physics challenge regressions, machine/destruction behavior and deterministic generation of both HTML distributions. **Real-device performance and exhaustive playthroughs remain unverified** until tested on representative older phones, browsers and PCs.

AI behavior is local and intentionally lightweight. It does not yet provide large-world route planning, autonomous blueprint construction, long-term social relationships, speech/dialogue, or learned physics puzzle solving. These would require later milestones.
