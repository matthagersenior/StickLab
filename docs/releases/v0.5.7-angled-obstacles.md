# StickLab v0.5.7 — Angled obstacle awareness

Go Here's local obstacle check now handles more scene context. It recognizes nearby fixed boxes that are rotated, avoids barriers beyond the requested destination, checks for overhead clearance before hopping, and keeps the closest geometry available in crowded scenes. Before these changes, the local planner could ignore angled blockers, attempt a hop below a ceiling, or miss a nearby wall when earlier scene objects filled its candidate limit.

## Movement change

- **Rotated fixed boxes:** the planner computes a conservative axis-aligned bounding box for each nearby rotated box and checks whether it intersects the figure's travel corridor.
- **Safe hop decisions:** only nearly level, ground-level boxes no wider than 72 world units remain candidates for an ordinary physical hop. Wider or angled structures are recognized as blockers but are not treated as climbable.
- **Headroom:** a possible hop is suppressed when a nearby fixed box intersects the figure's estimated head-clearance arc over the obstacle.
- **Destination awareness:** Go Here ignores a blocker that lies beyond the selected destination.
- **Crowded scenes:** AI input keeps the 32 nearest local objects, rather than the first 32 objects in creation order. Nearby walls and hazards are less likely to be omitted by earlier props.
- **Existing recovery:** a blocked destination remains saved, and the existing feedback invites the player to move the obstacle or choose another destination.

This is still local obstacle-aware movement, not complete pathfinding. Complex routes, climbing, grasping, and coordinated figure interactions need further development. The conservative bounds can report a rotated box as blocking even when its exact shape leaves a narrow passage; the headroom check is a local estimate, not a full-body collision simulation. The planner does not evaluate narrow passages or construct detours.

No scene format, save data, physics collision, or manual control behavior changes in this release.
