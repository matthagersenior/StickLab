# StickLab v0.4.2 — Portrait, landscape, and touch-tablet layout

This release responds to a screenshot from an Android phone showing overlapping title, Pause, camera, and movement controls.

## Changes

- Portrait phones: the world-title chip and four key actions occupy separate full-width rows, so no button sits behind another.
- Landscape phones and short touch displays: a compact single-row action header, horizontal camera controls, and movement pad on the opposite side of the world. Nonessential status chips are hidden to preserve gameplay room.
- Touch tablets: the full-size playable canvas remains available with a sliding tools menu, bottom tools strip, and on-screen movement controls. Desktop users retain the side panel and keyboard controls.
- Portrait phones with very little height: camera controls switch into a horizontal row to avoid touching the D-pad.
- Safe areas: header, camera, movement pad, and tool strip account for display cutouts and bottom navigation insets where provided.
- Orientation and viewport changes: the Canvas resizes without resetting the player's zoom/pan, and the tools-menu visibility follows touch capabilities, not only window width.
- Pause: removed the redundant Canvas-drawn pause badge that was appearing beneath the real header. The Play/Pause button and subtitle still indicate simulation status.
- A new installable-app cache version replaces old layouts, retaining network-first online updates and offline fallback.

## Verified screen sizes

Automated **real-Chrome DOM geometry tests** assert that critical controls remain inside the viewport and that the world header, action row, camera, D-pad, status, and tool strip do not overlap. Covered screen sizes in CSS pixels:

| Category | Width × Height |
| --- | --- |
| Small portrait | 320 × 480, 320 × 568 |
| Modern Android portrait | 360 × 800, 390 × 844 |
| Phone landscape | 568 × 320, 667 × 375, 800 × 360, 844 × 390 |
| Touch tablet | 768 × 1024, 1024 × 768 |
| Desktop | 900 × 600, 1440 × 900 |

An additional in-browser test rotates a running session portrait → landscape → portrait, then checks tool-menu interaction, selected tool state, and camera zoom while monitoring JavaScript errors.

Physics, save/load, resident AI, and challenge behavior remain unchanged. The standalone HTML remains dependency-free and self-contained; Playwright is a **test-only CI dependency**.

## Limits

No software can guarantee compatibility with literally every computing device. StickLab requires a browser supporting HTML5 Canvas and sufficient JavaScript and memory resources. Screen-layout checks cover representative sizes and Chrome touch emulation; specific older Safari, Firefox, embedded WebViews, and physical devices still merit testing. Extreme display sizes below 320 × 320 CSS pixels, high system text enlargement, or browser accessibility overlays may require additional layout adaptation.
