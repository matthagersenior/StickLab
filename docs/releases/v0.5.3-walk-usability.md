# StickLab v0.5.3 — One-Tap Walk on Phones

## Issue reproduced

On a narrow Android screen, Walk/Go Here was below the fold in the sidebar and was disabled unless the user had already selected a particular ragdoll joint with Grab. In the reported screenshot there was one living resident, Physics Puzzles was chosen but no challenge was started, and the simulation was paused. The player had no obvious way to begin autonomous movement.

## Changes

- **Walk** is a prominent tool immediately beside **Grab** in the mobile bottom strip and sidebar construction tools.
- One tap on Walk **automatically selects the nearest on-screen stick figure**; if no figure exists, it prompts the player to create a Resident or Ragdoll.
- A visible control-pad message says to tap a destination. The figure stays selected during targeting; pressing Grab cancels targeting without changing the world.
- After the player taps the playfield, Walk assigns the destination, re-enables autonomous AI if it had been disabled, and automatically resumes the simulation if paused.
- The closing tools drawer no longer intercepts the next touch.
- The existing menu button **Walk to a point** uses exactly the same flow, rather than requiring a separate Grab selection.
- All physics and resident movement still use the lightweight v0.5.2 gait controller, preserving gravity, collision checks and low-end device profiles.
- PWA cache version updated so mobile browsers fetch the new controls; the offline standalone HTML contains the same changes.

## Testing

Node regression tests cover no initial selection, paused physics, disabled AI, a complete touch destination command, actual figure movement, canceling, and the no-figure state. The Android-sized Chrome browser test reproduces the paused Physics Puzzles mode with a resident and verifies walking from both a scrolled sidebar and the bottom toolbar. The existing viewport, orientation, puzzle, save, machine and distribution tests run in the same GitHub Actions workflow.

**Limitation:** Go Here remains horizontal, reactive walking rather than full pathfinding over arbitrary obstacles. Character recovery from falls is not yet guaranteed.
