# StickLab v0.4.1 — Mobile controls and camera fix

**Reported on Android mobile browser:** Lower-right movement pad appeared inert when the Resident creation tool was selected. The upper-right camera buttons gave no indication whether they worked, while Recenter could reset to the same view. Some installed web apps could remain on an old copy because Pages navigation was served cache-first.

## Corrections

- The left/right/jump controls now select an existing stick figure automatically if none is controlled. Living residents visible in the viewport are preferred; the view focuses on the controlled figure and switches to Grab. The bottom pad reports the character name. If no figure exists, the game explicitly tells the player to place one instead of doing nothing.
- Holding left/right moves the selected figure through ordinary ragdoll physics. A short jump tap is queued until the next physics update rather than lost on pointer-up. Pressing a direction while paused starts the simulation.
- Camera +/− buttons announce the current zoom, show a persistent percentage, and use larger touch targets. Recenter explicitly reports when it resets the view.
- The GitHub Pages service worker has a new cache version and uses network-first **navigation** with an offline fallback, preventing stale control UI from persisting indefinitely on devices that reconnect. Already-open tabs may still need a reload after the worker activates.
- Existing physics challenges, world saves, AI agents, tools and compatibility guarantees remain unchanged.

## Verification

Automated UI-handler regressions check no selected figure, empty worlds, movement, jump tap queueing, camera zoom/reset feedback, Pause/Step, and deterministic standalone/hosted outputs. CI also checks the navigation cache policy.

The fix was driven by the user screenshot and review of handlers. Browser emulation and physical Android touch testing are separate checks; test results on their particular device cannot be guaranteed without an on-device retest.
